# 企业知识库准确率对照实验

> **一句话结论**：把教科书式的优化全上一遍——父子分块、混合检索、Rerank、结构化提示词——准确率 **67.5% → 67.5%，一分没涨**。
> 但在检索层加了一道「主体过滤」之后，**67.5% → 87.5%**，其中「张冠李戴」类错误从 **20% 修到 80%**。

---

## 要解决什么问题

企业知识库最危险的错误不是「瞎编」，而是**「把别家的规定当自家的」**——答案语气笃定、格式规范、甚至标注了出处，但内容来自另一家公司的同名制度。这类错误在人工抽查中极难发现，却在真实企业里天天发生：集团与子公司制度并存、并购后新旧制度混用、模板文件互相copy。

本实验要验证的判断是：**这类错误属于检索层问题，靠调提示词治不好。**

## 实验设计

三组知识库，语料完全相同，只有分块 / 检索 / 提示词不同：

| | KB-A 基线 | KB-B 优化 | KB-C 主体过滤 |
|---|---|---|---|
| 分块 | 固定 500 字（会切断条款） | 父子分块（子块按「第X条」切，父块含上下文） | 同 KB-B |
| 检索 | 纯向量 TopK=3 | 向量 + BM25 混合 → 候选 6 → Rerank → 3 | 同 KB-B **+ 检索阶段主体过滤** |
| 提示词 | 最简版 | 结构化版（含主体识别 + 强制拒答） | 同 KB-B |

**三边共用**：同一 Embedding 模型（bge-m3）、同一 LLM（Qwen2.5-7B-Instruct）、temperature=0、同一 20 题、每题独立调用（无上下文污染）。

**对照是干净的**：实测 KB-A 194 块（平均 489 字），KB-B 631 子块（平均 132 字）/ 父块平均 471 字，两组送进模型的上下文长度接近（约 1500 字）——KB-B/KB-C 赢不是因为「塞了更多内容」。

### 语料：故意制造混淆

12 份上市公司公开披露制度（来源：巨潮资讯网，证监会指定信息披露平台）：

| 分组 | 份数 | 公司 | 作用 |
|---|---|---|---|
| A 组 | 8 份 | 百川畅银（300614） | 知识库主体，20 道题的提问对象 |
| B 组 | 2 份 | 嘉益股份（301004） | 同类制度的**别家版本** |
| C 组 | 2 份 | 西宁特钢（600117） | 同类制度的**别家版本** |

B / C 组是故意混进库里的干扰项——检索时确实会被召回，陷阱生效。完整清单见 [`corpus/语料清单.md`](corpus/语料清单.md)。

### 评测集

20 题，按难度分四类，每题附**标准答案**、**出处（具体到条款）**、**评分要点**：

| 类型 | 题数 | 考察什么 |
|---|---|---|
| A 类 直接事实 | 8 | 单条款内的直接检索 |
| B 类 跨条推理 | 4 | 需要综合多个条款 |
| C 类 边界陷阱 | 5 | 同名制度分属不同主体，易张冠李戴 |
| D 类 应拒答 | 3 | 库里没有答案，考察是否敢说「不知道」 |

**关键前提**：先用人工核对确认每题的标准答案在语料中确实成立、且唯一，**再拿它去测模型**。这一步比搭知识库更耗时，但它决定了实验结论可不可信——如果标准答案本身有争议，后面所有数字都是废的。

## 结果

20 题 × 3 组 × 2 轮 = **120 次问答**。人工判分（两轮一致后取值），评分口径见 [`manual_scores.json`](manual_scores.json)。

| 题型 | 题数 | KB-A 基线 | KB-B 优化 | KB-C 主体过滤 |
|---|---|---|---|---|
| A 类 直接事实 | 8 | 8.0 (100%) | 7.0 (88%) | 8.0 (100%) |
| B 类 跨条推理 | 4 | 1.5 (38%) | 2.0 (50%) | 2.5 (62%) |
| C 类 边界陷阱 | 5 | 1.0 (20%) | 1.5 (30%) | **4.0 (80%)** |
| D 类 应拒答 | 3 | 3.0 (100%) | 3.0 (100%) | 3.0 (100%) |
| **合计** | **20** | **13.5 (67.5%)** | **13.5 (67.5%)** | **17.5 (87.5%)** |

### 两个发现

**发现一：标准优化手段全上，一分没涨。**
KB-B 同时改进了分块、检索、提示词三个环节——都是教科书写着的优化——总分纹丝不动。这说明**错误不在「怎么问」，而在「拿什么来答」**。

**发现二：病根在检索层，不在提示词层。**
加「主体过滤」（检索阶段只允许目标公司的文档进入上下文）后，C 类从 20% 直接到 80%，总分 67.5% → 87.5%。

值得注意的是 KB-B 在 A 类直接事实上反而从 100% 掉到 88%：父子分块让子块更短更精确，但也可能丢掉条款的前置条件。**这提示分块策略不是越细越好**，需要按题型权衡。

## 怎么复现

```bash
pip install -r requirements.txt
export SILICONFLOW_API_KEY=sk-你的密钥      # Windows: set SILICONFLOW_API_KEY=sk-...

python verify.py                            # ① 不调 API，本地重算结果表
python run_experiment.py --mock --limit 3   # ② 离线冒烟，验证流程可通
python run_experiment.py                    # ③ 跑全量（20 题 × 3 组 × 2 轮 = 120 次）
python score.py                             # ④ 自动初判，输出待人工复核条目
```

`verify.py` 是**不需要 API key 的**——它直接从 `manual_scores.json` 重算汇总表，用来确认本文的数字与原始数据自洽。先跑这条。

模型走硅基流动的 OpenAI 兼容接口：Embedding `bge-m3`、Rerank `bge-reranker-v2-m3`、LLM `Qwen2.5-7B-Instruct`，均为免费模型，跑完 120 次成本约等于零。

脚本支持**断点续跑**：中断后重新执行会跳过已完成条目，Embedding 结果缓存为 `.npy`，不会重复计费。

## 局限

诚实说明边界，结论才立得住：

- **样本量小**：20 题，结论是方向性的，不是精确值。C 类只有 5 题，单题改动就会让百分比跳动 20 个点
- **单一领域**：只测了上市公司内部制度这一类文本，未验证在合同、技术文档、产品手册上的表现
- **判分有主观成分**：已公开评分口径与逐条判分理由（`manual_scores.json` + `scores.json`），欢迎复核推翻
- **模型规格**：用 Qwen2.5-7B 小模型。换成更强的模型，绝对数值会变，但「检索层问题不该在提示词层解决」这个方向性判断大概率不变——**这一点未经验证，是推测**
